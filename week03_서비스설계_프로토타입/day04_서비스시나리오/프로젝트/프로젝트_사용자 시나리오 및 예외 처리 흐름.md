# Day 04 프로젝트 실습

## 건강한하루 사용자 시나리오 및 예외 처리 흐름

> Day01(User Story·MVP), Day02(IA·User Flow), Day03(화면설계서)에서 정리한 내용을 바탕으로, **"건강한하루"** 의 정상 시나리오와 예외 처리 흐름, 오류 메시지를 작성합니다.

---
## 실습 목표
- MVP 핵심 화면(Day03 스크린리스트)을 하나의 정상 시나리오(User Scenario)로 연결한다.
- 정상 흐름의 각 단계에서 발생할 수 있는 예외 상황을 찾는다.
- 예외 상황마다 사용자에게 보여줄 오류 메시지와 다음 행동을 설계한다.
- 정상 흐름과 예외 흐름을 하나의 표로 정리해 화면설계서와 연결한다.

---
## 실습 흐름
```
Day01 User Story·MVP 확인
  ↓
Day02 User Flow 확인
  ↓
Day03 스크린리스트·검증 시트 확인
  ↓
정상 시나리오(User Scenario) 작성
  ↓
단계별 예외 상황 찾기
  ↓
오류 메시지 설계
  ↓
정상 흐름·예외 흐름 종합표 작성
```

# 페르소나와 정상 시나리오

---
## 페르소나
| 항목 | 내용 |
| --- | --- |
| 이름 | 김하늘 (32세, 직장인) |
| 상황 | 모니터를 오래 보는 업무 특성상 눈이 쉽게 피로해지고, 만성 피로도 함께 겪고 있다 |
| 고민 | 영양제 종류가 너무 많아 무엇을 골라야 할지 몰라 검색만 반복한다 |
| 목표 | 내 상태에 맞는 영양제를 빠르고 안전하게 고르고 싶다 |

> Day01 User Story의 "선택이 어려운 사용자"를 구체적인 한 사람으로 표현한 것입니다.

---
## 정상 시나리오 (User Scenario)
1. 점심시간, 김하늘 님은 건강한하루 홈 화면에서 '눈 피로' 카테고리 칩을 눌러 건강고민입력 화면으로 들어간다.
2. '눈 피로'와 '피로감'을 선택하고 '맞춤 추천 받기'를 누르자, AI가 근거와 함께 상품 5개를 추천한다.
3. 추천 결과 화면에서 권장·상한 섭취량을 함께 확인한 하늘 님은 첫 번째 상품인 루테인 지아잔틴을 눌러 상세 페이지로 이동한다.
4. 성분 쉬운 설명과 섭취방법을 읽고 상한섭취량을 넘지 않는다는 것을 확인한 뒤, 안심하고 '구매하기'를 누른다.

---
## 정상 흐름을 화면 단위로 정리
| 단계 | 화면(Screen ID) | 사용자 행동 |
| --- | --- | --- |
| 1 | 홈(UI-W-001) | '눈 피로' 카테고리 칩 선택 |
| 2 | 건강고민입력(UI-W-002) | 고민 선택 후 '맞춤 추천 받기' 클릭 |
| 3 | 추천결과(UI-W-003) | 추천 상품·근거·섭취량 확인 |
| 4 | 상품상세(UI-H-004) | 성분 설명·섭취방법 확인 후 구매 결정 |

> Day02 User Flow(Step1~6)와 Day03 스크린리스트를 그대로 이어 붙인 것이 정상 시나리오입니다.

# 예외 상황 찾기

---
## 정상 흐름 각 단계에 예외 질문 던지기
| 단계 | 예외 질문 |
| --- | --- |
| 건강고민입력 | 사용자가 고민을 하나도 선택하지 않으면? |
| 추천 생성 | 조건에 맞는 상품이 하나도 없으면? |
| 추천결과 확인 | 추천을 믿지 못하거나 응답이 늦게 오면? |
| 상품상세 확인 | 섭취량이 상한을 넘으면? |
| (Could) AI상담 | AI가 답을 찾지 못하면? |

> Day03 검증 시트(필수 입력 항목·유효성 체크)에 이미 정리된 상황을 시나리오 형태로 풀어서 확인합니다.

---
# 예외 흐름 1. 필수 정보 누락

---
## 상황과 흐름
> 김하늘 님이 건강고민을 하나도 선택하지 않고 '맞춤 추천 받기'를 누르려 한다.

```text
건강고민입력(UI-W-002)
→ 고민 미선택 상태로 버튼 클릭 시도
→ 필수 정보 누락 확인
→ "건강 고민을 1개 이상 선택해 주세요" 안내
→ 고민 선택 영역으로 포커스 이동
→ 고민 선택 후 다시 버튼 클릭
→ 추천결과(UI-W-003)로 이동
```

핵심: 버튼을 아예 눌리지 않게 막기보다, **무엇을 채워야 진행되는지**를 알려줍니다.

---
# 예외 흐름 2. 추천 결과 없음

---
## 상황과 흐름
> 조건에 맞는 추천 상품이 하나도 없다.

```text
건강고민입력(UI-W-002)
→ 맞춤 추천 받기
→ 추천 생성 결과 0건
→ 빈결과안내(UI-H-003-1) 오버레이 표시
→ "조건에 맞는 추천 결과가 없어요" + 이유 안내
→ '건강고민 다시 입력하기' 버튼 클릭
→ 건강고민입력(UI-W-002)로 복귀(이전 선택값 유지)
```

핵심: 결과 없음은 막다른 길이 아니라 **조건을 조정해 다시 시도할 수 있는 지점**입니다.

---
# 예외 흐름 3. 상한섭취량 초과 경고

---
## 상황과 흐름
> 상품상세에서 확인한 제품의 1일 섭취량이 상한섭취량에 가깝거나 초과한다.

```text
상품상세(UI-H-004)
→ 섭취방법·주의사항 확인
→ 상한섭취량 초과 여부 판단(규칙 기반, Day04 이론 AI 적용 가능성 검토 결과)
→ 예: 과다섭취 경고 배너 노출
→ 섭취 전 확인 문구 안내
→ 사용자가 섭취량을 인지한 채 구매 여부 결정
```

핵심: 건강과 직결된 판단은 AI가 아니라 **정해진 기준표(규칙 기반)** 로 처리합니다(Day01 MVP 정책과 동일).

---
# 예외 흐름 4. AI 응답 신뢰도 낮음 (Could, RF-3)

---
## 상황과 흐름
> AI상담(RAG FAQ)에서 근거 문서를 찾지 못해 답변 신뢰도가 낮다.

```text
AI상담(UI-W-005)
→ 질문 입력
→ 근거 문서 검색
→ 근거를 찾지 못함
→ 추측 답변 대신 "정확한 답변을 찾지 못했어요" 안내
→ 'CS 상담 연결' 버튼 강조 노출
→ 사용자가 CS 상담으로 이동
```

핵심: AI는 모든 질문에 답하지 않고, **답할 수 없을 때를 스스로 알려야** 합니다.

---
# 예외 흐름 5. 응답 지연

---
## 상황과 흐름
> 추천 생성 또는 AI상담 응답이 기준 시간(NFR-1.0: 추천 2초, RAG 5초)보다 오래 걸린다.

```text
추천 요청 또는 질문 전송
→ 처리 중 상태 표시(로딩 인디케이터)
→ 기준 시간 초과
→ "요청이 지연되고 있어요. 잠시 후 다시 시도해 주세요" 안내
→ 입력 내용은 그대로 유지
→ 사용자가 다시 시도 또는 대기
```

핵심: 사용자가 "멈췄다"고 느끼지 않도록 **진행 상태와 예상 대기**를 함께 보여줍니다.

# 오류 메시지 설계

---
## 건강한하루 오류 메시지 표
| 상황 | 메시지 | 다음 행동 |
| --- | --- | --- |
| 필수 정보 누락 | 건강 고민을 1개 이상 선택해 주세요. | 고민 선택 영역으로 이동 |
| 추천 결과 없음 | 조건에 맞는 추천 결과가 없어요. | 건강고민 다시 입력하기 |

---
| 상황 | 메시지 | 다음 행동 |
| --- | --- | --- |
| 상한섭취량 초과 | 권장 상한섭취량을 초과할 수 있어요. 섭취 전 확인해 주세요. | 섭취방법 다시 확인 |
| AI 답변 신뢰도 낮음 | 정확한 답변을 찾지 못했어요. 상담원에게 연결해 드릴까요? | CS 상담 연결하기 |
| 응답 지연 | 요청이 지연되고 있어요. 잠시 후 다시 시도해 주세요. | 다시 시도하기(입력값 유지) |

---
## 메시지 점검: 나쁜 예 vs 건강한하루 적용
| 나쁜 메시지 | 건강한하루 메시지 |
| --- | --- |
| 오류가 발생했습니다 | 요청이 지연되고 있어요. 잠시 후 다시 시도해 주세요. |
| 잘못된 입력입니다 | 건강 고민을 1개 이상 선택해 주세요. |
| 결과 없음 | 조건에 맞는 추천 결과가 없어요. 건강고민을 다시 입력해보세요. |
| 사용 불가 | 정확한 답변을 찾지 못했어요. 상담원에게 연결해 드릴까요? |

모든 메시지에 **상황 + 다음 행동**이 함께 들어가도록 확인합니다.

# 정리
- User Scenario는 Day01 User Story와 Day02 User Flow를 "한 사람의 이야기"로 이어 붙인 것입니다.
- 정상 흐름의 각 단계마다 예외 질문을 던지면 예외 흐름을 빠짐없이 찾을 수 있습니다.
- 건강한하루의 예외 흐름은 필수 정보 누락, 결과 없음, 상한섭취량 초과, AI 신뢰도 낮음, 응답 지연 5가지입니다.
- 오류 메시지는 항상 "상황 설명 + 다음 행동"을 함께 담아야 사용자가 다시 앞으로 나아갈 수 있습니다.
- 상한섭취량처럼 건강과 직결된 예외는 AI가 아니라 규칙 기반으로 판단한다는 원칙(Day01 MVP 정책)을 예외 흐름에서도 그대로 지킵니다.
