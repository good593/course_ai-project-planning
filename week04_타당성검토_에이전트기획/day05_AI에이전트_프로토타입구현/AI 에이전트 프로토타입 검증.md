# AI 에이전트 프로토타입 검증

AI Agent가 사용자에게 실제로 도움이 되는지 확인하는 방법

---

## 오늘의 핵심 질문

AI 에이전트 프로토타입은 단순히 "응답이 나온다"로 검증할 수 없습니다.

기획자는 다음 질문에 답할 수 있어야 합니다.

- 사용자의 요청을 제대로 이해했는가?
- 필요한 도구나 정보를 적절히 사용했는가?
- 결과가 사용자의 의사결정이나 행동에 도움이 되는가?
- 실패했을 때 사용자가 다음 행동을 알 수 있는가?

---

## 왜 검증이 필요한가

AI 에이전트는 일반 기능보다 결과가 흔들릴 가능성이 큽니다.

- 같은 요청도 표현에 따라 응답이 달라질 수 있음
- 외부 도구나 데이터 연결 결과에 영향을 받음
- 사용자가 기대한 수준과 AI의 응답 수준이 다를 수 있음
- 오류가 발생해도 그럴듯한 말로 포장될 수 있음

따라서 AI 기능 검증은 **정답 확인**이 아니라 **서비스 신뢰도 확인**에 가깝습니다.

---

## 검증의 기준

AI 에이전트 검증은 세 가지 관점에서 봅니다.

| 관점 | 확인할 질문 |
|---|---|
| 사용자 관점 | 사용자가 원하는 목표에 도달했는가? |
| 응답 관점 | 답변이 정확하고 이해하기 쉬운가? |
| 흐름 관점 | 필요한 단계와 도구 사용이 자연스러운가? |

좋은 검증은 "AI가 똑똑한가?"보다
"사용자가 안심하고 사용할 수 있는가?"를 확인합니다.

---

## AI 기능 검증 방법

AI 기능은 다음 순서로 점검합니다.

1. 사용자 요청을 이해하는가
2. 필요한 정보를 구분하는가
3. 부족한 정보가 있으면 질문하는가
4. 적절한 도구 또는 절차를 선택하는가
5. 결과를 사용자가 이해할 수 있게 설명하는가
6. 실패 상황에서 대안을 제시하는가

이 순서는 AI 에이전트의 기본 동작 흐름을 확인하는 최소 기준입니다.

---

## 검증 전 준비할 것

검증을 시작하기 전에 기준을 먼저 정해야 합니다.

| 항목 | 예시 |
|---|---|
| 사용자 목표 | 회의 내용을 요약하고 다음 할 일을 정리한다 |
| 기대 결과 | 핵심 내용, 결정 사항, 담당자별 할 일이 구분된다 |
| 실패 기준 | 없는 내용을 만들어내거나 담당자를 잘못 지정한다 |
| 확인 질문 | 사용자가 이 결과를 바로 활용할 수 있는가? |

기준이 없으면 응답을 보고도 좋은지 나쁜지 판단하기 어렵습니다.

---

## 테스트 시나리오 유형

AI 에이전트는 다양한 상황에서 확인해야 합니다.

| 유형 | 확인 포인트 |
|---|---|
| 정상 요청 | 기본 기능이 기대대로 동작하는가 |
| 정보 부족 요청 | AI가 필요한 정보를 다시 묻는가 |
| 모호한 요청 | 임의로 판단하지 않고 기준을 확인하는가 |
| 도구 실패 | 실패 이유와 다음 행동을 안내하는가 |
| 위험한 요청 | 제한해야 할 내용을 안전하게 거절하는가 |
| 수정 요청 | 이전 응답을 반영해 개선하는가 |

정상 흐름만 보면 실제 서비스에서 발생할 문제를 놓치기 쉽습니다.

---

## AI 기능 검증 체크리스트

기획자는 다음 항목을 기준으로 기능을 점검할 수 있습니다.

- 사용자의 의도를 정확히 파악했는가
- 답변에 필요한 조건을 확인했는가
- 불확실한 내용을 단정하지 않았는가
- 도구 사용이 필요한 상황을 구분했는가
- 도구 결과를 응답에 올바르게 반영했는가
- 사용자가 다음 행동을 알 수 있게 정리했는가

체크리스트는 개발 지식보다 **서비스 판단 기준**을 세우는 도구입니다.

---

## 응답 품질 평가 기준

AI 응답 품질은 여러 기준을 함께 봐야 합니다.

| 기준 | 의미 |
|---|---|
| 정확성 | 사실과 데이터가 맞는가 |
| 관련성 | 사용자 질문에 직접 답하는가 |
| 완전성 | 필요한 내용이 빠지지 않았는가 |

---
| 기준 | 의미 |
|---|---|
| 명확성 | 사용자가 쉽게 이해할 수 있는가 |
| 일관성 | 같은 기준으로 반복 응답하는가 |
| 안전성 | 위험하거나 부적절한 답을 피하는가 |
| 유용성 | 사용자의 다음 행동에 도움이 되는가 |

> 품질 평가는 "말을 잘했는가"가 아니라 "쓸 수 있는 결과인가"를 보는 과정입니다.

---

## 5점 척도 평가 예시

| 점수 | 판단 기준 |
|---|---|
| 5점 | 바로 사용할 수 있고 수정이 거의 필요 없음 |
| 4점 | 핵심은 맞지만 일부 표현이나 구조 보완 필요 |
| 3점 | 사용할 수는 있으나 중요한 정보가 일부 부족 |
| 2점 | 방향은 맞지만 실제 활용하기 어려움 |
| 1점 | 의도 이해 실패 또는 잘못된 정보 포함 |

점수만 남기기보다 **왜 그 점수인지**를 함께 기록해야 개선으로 이어집니다.

---

## Agent에서 특히 봐야 할 것

AI Agent는 단순 답변보다 "행동 흐름"이 중요합니다.

- 어떤 상황에서 도구를 사용하는가
- 도구를 사용하지 않아도 되는 상황을 구분하는가
- 도구 결과와 AI 판단을 섞어 말하지 않는가
- 사용자 승인 없이 중요한 행동을 진행하지 않는가
- 실패했을 때 흐름을 멈추지 않고 대안을 제시하는가

Agent 검증은 응답 문장뿐 아니라 **판단 순서**를 함께 확인합니다.

---

## 나쁜 응답과 좋은 응답의 차이

사용자 요청:
"지난 회의 내용을 바탕으로 다음 할 일을 정리해줘."

| 구분 | 응답 특징 |
|---|---|
| 아쉬운 응답 | 회의 내용에 없는 일을 만들어내거나 담당자를 임의로 지정함 |
| 좋은 응답 | 확인된 내용만 정리하고, 담당자가 없는 항목은 미정으로 표시함 |

AI가 빠르게 답하는 것보다
**확인된 정보와 추정한 정보를 구분하는 것**이 더 중요합니다.

---

## 개선 포인트 도출

문제를 발견하면 원인을 분류해야 합니다.

| 문제 유형 | 개선 방향 |
|---|---|
| 요청 이해 문제 | 사용자 의도 파악 기준 보완 |
| 프롬프트 문제 | 역할, 제약, 출력 형식 명확화 |
| 정보 부족 문제 | 추가 질문 흐름 설계 |
| 도구 사용 문제 | 도구 사용 조건과 순서 재정의 |
| 데이터 문제 | 참고 데이터 범위와 최신성 확인 |
| 메시지 문제 | 오류 안내와 다음 행동 문구 개선 |

개선은 "AI가 이상하다"가 아니라 "어느 부분의 기준이 부족한가"로 정리해야 합니다.

---

## 개선 우선순위 정하기

모든 문제를 한 번에 고칠 수는 없습니다.

기획자는 다음 기준으로 우선순위를 정합니다.

- 사용자 목표 달성에 직접 영향을 주는가
- 자주 발생하는 문제인가
- 잘못된 답변이 큰 피해를 만들 수 있는가
- 적은 수정으로 개선 효과가 큰가
- MVP의 핵심 가치와 연결되는가

가장 먼저 고칠 것은 **자주 발생하고 사용자 신뢰를 크게 떨어뜨리는 문제**입니다.

---

## 검증 결과 정리 양식

| 항목 | 작성 내용 |
|---|---|
| 검증 시나리오 | 어떤 사용자 상황을 확인했는가 |
| 기대 행동 | AI가 어떻게 응답해야 하는가 |
| 실제 응답 | AI가 실제로 어떻게 반응했는가 |
| 문제 유형 | 이해, 품질, 도구, 데이터, 메시지 중 무엇인가 |
| 영향도 | 사용자에게 얼마나 큰 불편을 주는가 |
| 개선 결정 | 프롬프트, 흐름, 데이터, UI 중 무엇을 바꿀 것인가 |

검증 결과는 감상이 아니라 다음 수정으로 이어지는 기록이어야 합니다.

---

## 기획자가 가져야 할 관점

AI 에이전트 검증에서 기획자의 역할은 모델을 평가하는 사람이 아닙니다.

기획자는 다음을 판단합니다.

- 이 기능이 사용자의 문제를 실제로 줄이는가
- 사용자가 결과를 믿고 사용할 수 있는가
- 실패했을 때도 서비스 경험이 무너지지 않는가
- 개선해야 할 지점이 명확히 보이는가

AI 기능의 완성도는 기술 성능만이 아니라 **사용자 경험의 안정감**으로 판단됩니다.

---

## 오늘의 정리

AI 에이전트 프로토타입 검증은 세 단계로 볼 수 있습니다.

1. 기능이 사용자 목표에 맞게 동작하는지 확인한다
2. 응답 품질을 기준에 따라 평가한다
3. 문제 원인을 분류하고 개선 우선순위를 정한다

검증의 목적은 완벽한 AI를 찾는 것이 아니라
**사용자가 믿고 쓸 수 있는 서비스로 다듬는 것**입니다.
