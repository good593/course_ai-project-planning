# 왜 지금 Agent로 확장하는가

---
## 일반 챗봇(Day03)만으로 부족한 질문들
Day03 RF-3 AI상담은 **내부 DB(상품마스터·영양소_기능성_추천DB·권장섭취량)** 만 근거로 답합니다.

---
다음과 같은 질문에는 답할 수 없습니다.

| 질문 예시 | 이유 |
| --- | --- |
| "이 제품 최근에 리콜된 적 있어?" | 내부 DB에 회수·판매중지 정보가 없음 |
| "루테인 관련 최신 뉴스 있어?" | 내부 DB는 등록 시점 정보만 있고 최신 이슈가 없음 |
| "요즘 사람들이 많이 찾는 영양제가 뭐야?" | 내부 DB는 트렌드가 아니라 등록 상품만 담고 있음 |

> 이런 질문은 **최신 정보**가 필요하므로, 내부 DB를 아무리 잘 설계해도 풀리지 않습니다. → 외부 조회 Tool이 필요한 이유입니다.

---
## 일반 챗봇 vs AI Agent (RF-3 기준)
| 구분 | Day03 일반 챗봇 | Day04 AI Agent |
| --- | --- | --- |
| 정보 사용 | 내부 DB만 | 내부 DB + 외부 웹 검색(Tool) |
| 판단 | 근거 문서를 찾아 답변 | **어떤 정보가 필요한지 먼저 판단한 뒤, 필요하면 Tool을 선택해 호출** |
| 흐름 | 한 번의 답변 | 질문 파악 → Tool 선택 → Tool 실행 → 결과 반영 → 답변 |
| 위험 | 근거 부족 시 확인 요청 | Tool 실패·저신뢰 검색 결과까지 함께 고려 |

> RF-3은 이제 "내부 근거로만 답하는 챗봇"에서 "필요하면 인터넷도 찾아보는 Agent"로 역할이 넓어집니다.

# 외부 조회 Tool 설계

---
## Tool 후보 선정 기준
이론 문서의 "Tool Calling 설계에서 봐야 할 것"을 그대로 적용합니다.

| 질문 | 판단 |
| --- | --- |
| 어떤 사용자 문제를 해결하는가? | 리콜·부작용 등 안전 이슈를 놓치는 문제, 최신 정보 부재 문제 |
| 언제 AI가 이 Tool을 사용해야 하는가? | 내부 DB 검색으로 답이 안 나오고, 질문에 "최근", "리콜", "뉴스", "요즘" 같은 표현이 있을 때 |
| 잘못 쓰면 어떤 위험이 있는가? | 신뢰도 낮은 웹 결과를 사실처럼 전달할 위험 |
| 실행 전 사용자 확인이 필요한가? | 조회만 하므로 불필요(승인 기준은 뒤에서 별도 정의) |

---
## Tool 1. 성분·제품 최신 뉴스 검색
| 항목 | 내용 |
| --- | --- |
| 설명 | 특정 성분·제품과 관련된 최신 뉴스·이슈를 검색한다 |
| 입력 파라미터 | `topic: str` (예: "루테인", "프로바이오틱스") |
| 검색 도구 | TavilySearch (`topic="news"`) |
| 검색 대상 도메인 | 식품안전나라, 네이버뉴스 건강 섹션 등 신뢰 가능한 매체로 제한 |
| 권한 수준 | 조회 |
| 출력 | 뉴스 제목·요약·출처 URL 최대 3건 |

---
## Tool 2. 회수·안전성 경보 검색
| 항목 | 내용 |
| --- | --- |
| 설명 | 특정 건강기능식품의 회수·판매중지·부작용 경보를 검색한다 |
| 입력 파라미터 | `product_name: str` (예: "뉴메릿 비타민C&D 메가") |
| 검색 도구 | TavilySearch (`topic="general"`) |
| 검색 대상 도메인 | 식품안전나라 위해상품 판매차단, 식약처 보도자료, 소비자24 |
| 권한 수준 | 조회 |
| 출력 | 회수/경보 여부 요약, 발견 시 반드시 CS 상담 연결 안내 포함 |

> 두 Tool 모두 **조회 권한만** 가지며, 실행(구매취소, 신고 접수 등)은 하지 않습니다.

---
## Tool을 만드는 절차 (개념)

1. 검색 대상 도메인을 제한한 웹 검색 도구를 준비한다(신뢰 가능한 매체·공공기관 사이트로 한정)
2. 검색 도구를 "이름 + 한 줄 설명 + 입력 파라미터"를 가진 Tool로 감싼다
3. 검색 결과가 없을 때 반환할 안내 문구를 미리 정해둔다
4. 검색 결과가 있을 때는 제목·요약·출처 URL을 함께 반환하도록 만든다
5. Agent에게 이 Tool들을 등록하고, System Prompt에 "언제 이 Tool을 써야 하는지" 규칙을 함께 알려준다

# Workflow 설계

---
## RF-3 Agent Workflow
```text
사용자 질문 입력
→ 내부 DB(상품·영양소·섭취기준)로 답변 가능한지 AI가 먼저 판단
  → 가능: Day03 방식대로 근거 인용 답변 (Tool 미사용)
  → 불가능(최신 이슈·리콜·트렌드 질문): 아래로 진행
→ 적절한 Tool 선택 (search_supplement_news / search_recall_alert)
→ Tool 실행 → 검색 결과 반환
→ 결과가 있는가?
  → 예: 결과를 근거로 답변 생성 + 출처 URL 표시
  → 아니오: "찾지 못했다"고 안내 + CS 상담 연결 제안
→ 회수·경보가 발견되었는가?
  → 예: 경고 문구와 함께 CS 상담 연결을 강하게 권장
→ 사용자에게 최종 답변 제공
```

---
## System Prompt 확장 (day03 대비 추가되는 부분)
```text
(day03 System Prompt에 아래 규칙을 추가한다)

내부 데이터로 답할 수 있으면 내부 데이터를 우선 사용한다.
최신 뉴스, 리콜/회수 여부, 트렌드처럼 내부 데이터에 없는 질문만
search_supplement_news 또는 search_recall_alert 도구를 사용한다.
도구를 사용했다면 반드시 검색 결과의 출처 URL을 함께 제시한다.
도구 결과에도 없는 내용은 확신하듯 말하지 않는다.
회수·경보 정보를 발견하면 반드시 CS 상담 연결을 안내한다.
```

# 권한 범위와 승인 기준

---
## 권한 범위
| 구분 | 내용 |
| --- | --- |
| 할 수 있는 일 | 공개된 뉴스·공공기관 페이지를 검색해 요약·인용하는 것(조회) |
| 할 수 없는 일 | 웹 검색 결과만으로 섭취량·경고 여부를 최종 판단하는 것(RF-4는 여전히 내부 규칙 기반 DB가 우선) |
| 할 수 없는 일 | 특정 사이트에 글 작성, 구매, 신고 접수 등 실행 행위 |
| 할 수 없는 일 | 사용자 개인 식별 정보를 웹에서 검색하는 것 |

---
## 승인 기준 (Human-in-the-loop)
| 상황 | 처리 방식 |
| --- | --- |
| 일반 뉴스 조회 | AI가 바로 답변(자동, 저위험) |
| 회수·부작용 경보 발견 | AI가 안내는 하되, **CS 상담 연결은 사용자가 직접 선택**하도록 버튼만 제공(자동 연결 금지) |
| 검색 결과가 상충하거나 신뢰도 낮음 | 자동 답변 대신 "확인이 필요하다"고 안내 + 전문가 상담 권장 |

> RF-4(과다섭취 경고)와 같은 원칙: **AI는 제안까지만, 최종 확인은 사람.**

# 예외 처리

---
## Agent 예외 흐름 (이론 문서 표를 RF-3 기준으로 구체화)
| 예외 상황 | 대응 |
| --- | --- |
| Tool 호출 실패(API 오류·타임아웃) | "지금은 최신 정보를 가져오지 못했다"고 안내하고 내부 DB 근거로만 답변 |
| 검색 결과 없음 | 조건을 좁혀 다시 검색하거나, 없다고 정직하게 안내 |
| 권한 밖 요청(실행을 요구하는 질문) | "조회만 도와드릴 수 있다"고 안내하고 CS 상담 연결 제안 |
| 위험 요청(의학적 진단 요구) | day03 System Prompt 규칙대로 답변 범위를 제한 |
| 회수·경보 발견 | 경고 문구 + CS 상담 연결 버튼 강조 노출 |

# 성공 지표

---
## KPI (Day01 ROI KPI에 Tool 관련 지표 추가)
| KPI | 정의 | 목표 |
| --- | --- | --- |
| 상담 완료율 | 추가 문의 없이 종료된 비율(Day01 재사용) | 70% 이상 |
| 근거 인용률 | 답변에 출처가 포함된 비율(내부 DB + 외부 Tool 모두) | 100%에 가깝게 |
| Tool 호출 성공률 | Tool 호출 중 정상적으로 결과를 받은 비율 | 신규 지표, 첫 측정값을 기준선으로 기록 |
| 회수·경보 조기 안내 건수 | 외부 조회로 발견해 사용자에게 안내한 건수 | 신규 지표, 안전 가치 측정용(정성 효과와 함께 해석) |
